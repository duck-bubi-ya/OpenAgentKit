# ADR-0028：终态会话消息可选择写入本地库

状态更新（2026-11-20）：对外入口只在管理端「配置」页保存，不再写入环境变量。服务立刻向百炼登记 Webhook，
签名密钥写入数据目录，不返回给页面。`KIT_PUBLIC_BASE_URL` 继续只覆盖前端 `apiBaseUrl`，不充当回调地址。

## 背景

聊天正文一直以云上为原件。打开对话走实时流，Kit 数据库只存会话目录。企业希望终态之后的消息能留在自己的库里。百炼 Webhook 只通知会话结束，正文要再调用列出事件的接口获取。

## 决策

1. 默认关闭。同时配置公网地址 `KIT_PUBLIC_BASE_URL` 和签名密钥 `KIT_WEBHOOK_SIGNING_SECRET` 才挂上可用的回调，并启动进程内调度器。
2. 只在 `session.status_idled`、`session.status_terminated`，以及线程终态 `session.thread_idled`、`session.thread_terminated` 之后写入。回调只入队并立刻回复。调度器分页拉取列出事件的结果，按消息 id 写入 `kit_session_messages`。
3. 保存列出接口返回的消息字段。超限的一行不写、不截断，任务标失败。发送、打开对话和工具审批仍读云上。
4. 删除会话时，消息行和 `kit_sessions` 在同一次提交里删除。`session.deleted` 与 `session.archived` 不入队。

## 理由

通知包里没有正文，也不能在 5 秒的回调里拉完一个大会话。任务表把门铃和写入分开。默认关闭，避免没有公网地址的安装空转，也避免把密钥写进仓库。

## 后果

- 这一份是终态副本，不替代云上原件，也不加快正在进行的对话。
- 数据库备份会包含消息正文。日志、错误和审计不能写入正文或签名密钥。
- 这一期页面不读这张表。

## 备选方案

- 每次打开对话都把正文写入本地缓存：实时流和终态副本会缠在一起，本 ADR 不采用。
- 在回调请求里同步拉完全部消息：大会话会超时，并占住 SQLite 写入。
